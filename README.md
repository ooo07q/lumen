# 筆記 App 原型（本機伺服器版）

三欄：筆記樹｜筆記分頁｜潛在連結與建議。工具（`tools/wiki.py`、`jev.py`、`pdf2raw.py`）是 app 自己的一份，和任何筆記庫裡的 `tools/` 無關；用環境變數 `NOTES_VAULT` 指向目前打開的筆記庫。

```
python3 ~/NotesApp/server.py --open
```

啟動後終端機會印出一個帶存取碼的網址（`http://127.0.0.1:8765/?k=…`）。第一次要用這個網址打開，瀏覽器之後就記得（cookie）。

- 不給 `--vault`：打開上次用的筆記庫；第一次用會出現開始畫面（建立新的筆記庫，或打開一個資料夾）。
- `--vault 路徑`：直接打開這個資料夾。
- `--read-only`：完全不寫入。`--port 8765`（預設；被占用就自動換一個）、`--open`（自動開瀏覽器）。

開發用的本機筆記（測試用筆記庫在哪、怎麼重做）在 `NOTES.local.md`，不進 git。

## 筆記庫是什麼

任何資料夾都可以。

| 情況 | 你的筆記 | 日記 | 附件 |
|---|---|---|---|
| 資料夾裡有 `raw/` | `raw/` | Obsidian 日記設定的資料夾，沒有就 `raw/journal/` | `raw/assets/` |
| 沒有 `raw/`（新建的筆記庫、一般的 Obsidian vault） | 除了 `wiki/`、`tools/`、`templates/` 和隱藏資料夾以外的全部 | Obsidian 日記設定的資料夾，沒有就 `journal/` | `assets/` |

`wiki/` 是 AI 整理出來的頁面，app 不改。新附件放在 Obsidian「附件資料夾」設定的位置（在筆記範圍內的話），否則放 `assets/`。

在 app 裡建立的新筆記庫：`journal/`、`assets/`、`wiki/`（index、log、Overview）、`templates/journal.md`，和 Obsidian 的設定（附件放 `assets/`、日記放 `journal/`），用 Obsidian 也能直接打開。

## 檔案放在哪

| 東西 | 位置 |
|---|---|
| App 的程式 | `~/NotesApp/`（git 記錄版本）：`server.py`、`static/`、`tools/`、`scaffold/`（新筆記庫的樣板）、`html2md.py` |
| App 的資料 | `~/Library/Application Support/NotesApp/`：`settings.json`（筆記庫清單）、`access_key`（存取碼，只有你的帳號能讀）、`protected.txt`（一律唯讀的筆記庫）、`vaults/<名字>-<路徑代碼>.json`（每個筆記庫的狀態：略過的建議、Jev 對筆記的判斷） |
| 工具的快取 | `vaults/<名字>-<路徑代碼>/`（同一個資料夾裡）：只由 app 自己的工具產生，從零開始。筆記庫裡如果有自己的 `tools/`，app 一律不讀 |
| 版本紀錄 | 筆記庫的 `.notesapp/history/<筆記路徑>/<時間>.md` |
| 刪除的檔案 | 筆記庫的 `.trash/`（Obsidian 的垃圾桶） |

## 存取

伺服器只聽本機（127.0.0.1）。每個請求都要以 `127.0.0.1:埠` 或 `localhost:埠` 為 Host（擋 DNS rebinding）；讀寫筆記（`/api`、`/file`）還要存取碼的 cookie（HttpOnly、SameSite=Strict）；POST 另外檢查 Origin。這擋的是「你瀏覽的其他網站透過瀏覽器碰你的筆記」；同一個帳號下的其他程式本來就能直接讀檔案，存取碼擋不住，也不是為了擋它們。

## 功能

| 區塊 | 內容 |
|---|---|
| 頂端 | 筆記庫名稱：點一下切換筆記庫、打開其他資料夾、建立新的筆記庫、在 Finder 中顯示；左右兩端的按鈕顯示／隱藏左右欄（⌘\、⌘⇧\）；一個框找東西也問 AI：打字比對標題、別名、中文名（繁簡互通，Jev 開時再列 Jev 判斷的相關頁），Enter 搜內容，⌘↵ 問 AI（像問題的句子會把「問 AI」排第一）；⌘K；Jev 開關 |
| 左欄 | ＋今天的日記、＋新筆記（右鍵點資料夾：在這裡新增）；日記、筆記（資料夾／待整理）、附件、知識庫；搜尋結果 |
| 中欄 | 上一頁／下一頁；多分頁；Markdown 顯示；編輯、⌘S；點標題改名（檔名和 frontmatter 的 `title:` 一起改，沒存的修改先存）；「版本」看以前的版本、和現在的差別、還原；PDF 轉出來的筆記預設整理排版（只影響顯示）；附件預覽；網頁轉成筆記；矛盾的並排比較 |
| 右欄 | 「這篇」：建議、記下的爭議、整理狀態、這篇的附件、潛在連結、已連結、誰連到這頁。「✦ AI」：對話（見下） |
| 檔案 | 從 Finder 拖進左欄匯入；拖曳換資料夾；改名（右鍵「改名…」，連到它的 `[[連結]]` 一起更新）；刪除到 `.trash/`，可復原。只限你的筆記和附件；日記不能搬出日記資料夾 |

## 問 AI（Claude Code，只回答）

用這台電腦登入的 Claude Code 回答（`claude` 指令，用你的 Claude 帳號額度；沒裝或沒登入時，對話裡會說明）。app 先用自己的工具找相關的頁（Jev 開：Jev 判斷每頁；關：關鍵字），連同目前打開的筆記（可以拿掉）交給 Claude；日記和從日記整理出來的頁永遠不送。Claude Code 以「沒有任何工具」執行：不能開檔案、不能執行指令、不會改任何東西；不載入你的設定、hooks、MCP，工作資料夾是 app 資料夾裡的空資料夾 `agent/`，所以不讀任何 CLAUDE.md。回答逐字出現，可以停止；頁面連結可以點；「讀了幾頁」列出送了哪些頁。

模型在 AI 分頁底下選（瀏覽器記得你的選擇）：

| 選項 | 怎麼選模型 |
|---|---|
| 自動（預設） | Jev 看問題和找到的頁（只有標題和摘要），判斷難度：查一個事實 → Haiku；說明、連結幾頁 → Sonnet；深入論證、長文 → Opus（想得較多）。Jev 關著或沒回應 → Sonnet |
| Haiku／Sonnet／Opus | 固定用這個。Opus 最耗額度 |

旁邊的「思考」選單決定想多深（effort）：自動（預設）時，問題裡說「簡單說」就想少一點、說「仔細想」就想仔細，沒說就由 Jev 判斷（Jev 關著是一般）；Opus 自動時至少「想得仔細」（見下）。你在選單選的一律優先。

回答下面寫用了哪個模型、想多深、為什麼。Opus 在這種用法下，如果沒先思考就開始回答，常會把它的思考或 Claude Code 的內部說明混進回答：app 一看到這種開頭就停掉重問，3 次都這樣就改用 Sonnet（回答下面會寫）。開頭是奇怪標籤的回答也會重問。「存成分析頁」「整理這篇」交給 agent（見下一節）。

## AI 整理知識庫（agent）

會動手的部分，一樣用這台電腦登入的 Claude Code。三種工作：
- **整理一篇筆記**：右欄「這篇」的「✦ 請 AI 整理這篇」，或 AI 回答下的「整理「…」」。寫來源頁、更新相關的概念・人物頁、Overview、log。
- **存成分析頁**：AI 回答下的「存成分析頁」。寫 `wiki/analyses/` 的一頁，相關的頁連回來。
- **檢查知識庫**：點左上角筆記庫名稱 →「✦ 請 AI 檢查知識庫…」。

每個工作分兩步，在右欄 AI 分頁：
1. **擬計畫**：AI 只讀不寫，讀筆記、查相關的頁，列出重點和要新增、更新哪些頁。你可以寫下想改的地方，按「照這樣做」或「不要做」。
2. **動手**：照計畫寫。做完列出每個改過的檔案（可以看差異），「全部復原」把這次的修改一次放回去；改之前的內容也留在版本紀錄裡。

限制（Claude Code 的權限規則加上 app 自己的工具伺服器 `tools/agent_mcp.py`，不是只靠指示）：
- 只能寫 `wiki/`；你的筆記、附件、PDF 一律不能改、搬、刪。做完 app 會檢查知識庫以外有沒有檔案變動。
- 不能讀日記、從日記整理出來的頁、`.notesapp/`（版本紀錄）、`.trash/`。
- 沒有終端機、沒有網路：一般的終端機指令能繞過讀取限制（例如 `grep -r`），所以 agent 改用 app 提供的固定工具（搜尋、整理前分析、cite、lint、Jev 的檢查）。
- 不讀筆記庫裡的 CLAUDE.md 或你的 Claude Code 設定；指示是 app 自己的 `agent/instructions.md`。

模型和思考深度用 AI 分頁底下的選單；「自動」時整理和檢查用 Sonnet、想得仔細，存分析頁用 Sonnet、一般。費用顯示在每個工作下面（以 API 價格換算，實際扣的是你的 Claude 額度）。

## 版本紀錄

存檔前，如果內容有變，先把舊的內容留成一版。連續寫作時 10 分鐘最多留一版（留的是這段寫作開始前的樣子），每篇最多 100 版。改名、搬移時版本跟著走；改名時被更新連結的筆記也各留一版；還原前先把現在的內容留成一版，所以還原也能復原。

## PDF 筆記的整理排版

只在畫面上：把斷在句子中間的行和跨頁的段落接起來（中文直接接，英文接空格、去掉行尾連字號），去掉每頁頂端或底端重複出現的頁首頁尾和單獨的頁碼，拿掉圖片的 OCR 文字（除非整篇幾乎都是圖片文字），頁碼標記變成分隔線。按「顯示原始排版」看原樣。對測試複本的 5,248 篇 PDF 筆記檢查過：保留 99.85% 的文字、全部 7,385 張圖。

## 名稱比對
